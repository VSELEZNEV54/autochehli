# Бэкенд «Автостиль»: запуск и обслуживание

Сайт — статические страницы (`*.html`, `css/`, `js/`, `assets/`). Бэкенд — `backend/`: Python 3.12, FastAPI, SQLite или PostgreSQL.
Он принимает заказы и заявки, создаёт платежи в ЮKassa, расшифровывает VIN, шлёт уведомления менеджерам и даёт админку.

## Как устроено

| Что | Где |
| --- | --- |
| API для сайта | `app/routers/public.py` — `/api/orders`, `/api/requests`, `/api/vin`, `/api/vin/suggest` (подсказки при вводе), `/api/orders/<id>`, уведомления ЮKassa |
| Админка | `app/routers/admin.py`, шаблоны `app/templates/admin/` — `/admin` |
| Заказы, оплаты | `app/services.py`, `app/payments/` (ЮKassa, тестовая касса) |
| VIN | `app/vin/decoder.py`, справочники `app/vin/sources/*.json` |
| Каталог и цены | читаются из сайта: `js/data.js` (лекала и цены) и `js/app.js` (сочетания `VARIANTS`) |
| Защита | `app/security.py` (лимиты, Origin, антиспам, пароли, 2FA), `deploy/nginx.conf` |
| Тесты | `tests/` — `python -m pytest` |

**Цены считает сервер.** Браузер присылает только «что» (лекало + сочетание + количество), сумму сервер берёт из каталога.
Тесты `test_catalog_sync.py` ловят расхождение, если в JS поменяли сочетания, доставку или материалы конструктора.

### Путь заказа

1. Корзина (`js/cart-page.js`) → `POST /api/orders`: позиции, доставка, способ оплаты, получатель, VIN, допы, согласие на ПДн.
2. Сервер проверяет данные, пересчитывает цены, сохраняет заказ `AS-100001`, сверяет VIN с лекалом.
3. Предоплата (1 000 ₽) или полная оплата — сервер создаёт платёж в ЮKassa и возвращает ссылку; клиент уходит на страницу ЮKassa.
   Счёт для юрлица — без онлайн-оплаты, заказ сразу в админке (с организацией и ИНН, ИНН проверяется по контрольной сумме).
4. ЮKassa возвращает клиента на `thanks.html?order=…`; страница показывает номер и статус оплаты, при неудаче — кнопку «Оплатить».
5. ЮKassa присылает уведомление на `/api/payments/yookassa/webhook`. Сервер проверяет адрес отправителя и **перезапрашивает статус
   платежа в API ЮKassa** — поддельное уведомление ничего не изменит. Сумма у ЮKassa должна совпасть с суммой платежа.
6. Менеджерам — сообщение в Telegram и письмо: что заказали (марка, модель, кузов, салон, материал, цвет), сумма, оплата, доставка,
   получатель, VIN и ссылка на карточку в админке. Клиенту — письмо с номером заказа (если указал e-mail).
7. В админке: статус, трек-номер, заметки, ссылка на доплату остатка, отметка оплаты наличными / наложенным платежом / по счёту,
   сверка VIN с лекалом, выгрузка в Excel (CSV).

Заявки (конструктор, вопрос, сообщение с контактов, опт, отзыв) идут в ту же таблицу с типом и видны в админке на вкладке «Заявки».

## Запуск на компьютере

```bash
cd backend
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt pytest
.venv/bin/python -m app.cli create-admin admin
.venv/bin/uvicorn app.main:app --reload
```
Открыть http://127.0.0.1:8000 — сайт и бэкенд на одном адресе, оплата через тестовую кассу (деньги не списываются).
Админка — http://127.0.0.1:8000/admin. Тесты — `.venv/bin/python -m pytest`.

## Сервер

1. **VPS в России** (152-ФЗ: персональные данные граждан РФ хранятся на серверах в РФ) — Selectel, Timeweb Cloud, Yandex Cloud, REG.RU.
   Ubuntu 24.04, 1–2 vCPU, 2 ГБ памяти хватит с запасом.
2. Пользователь `avtostil`, папки `/opt/avtostil` (код) и `/var/www/avtostil` (сайт).
3. Сайт: `sh backend/deploy/publish.sh avtostil@сервер:/var/www/avtostil` — на сервер уходят только публичные файлы.
4. Бэкенд — Docker (`backend/docker-compose.yml`) или systemd (`backend/deploy/avtostil.service`).
   `cp .env.example .env`, заполнить, `docker compose up -d --build`, затем `docker compose exec app python -m app.cli create-admin admin`.
5. nginx: `deploy/nginx.conf` → `/etc/nginx/sites-available/`, `deploy/avtostil-proxy.conf` и `deploy/avtostil-headers.conf` → `/etc/nginx/snippets/`,
   сертификат `certbot --nginx -d 1avtochehol.ru -d www.1avtochehol.ru`.
6. Бэкапы базы: `deploy/backup.sh` в cron раз в сутки + копия вне сервера.
7. Мониторинг: `GET /api/health` (UptimeRobot, Яндекс Мониторинг), журналы — `docker compose logs` или `journalctl -u avtostil`.

После смены цен или каталога (`tools/build_data.py` → `js/data.js`) выложите сайт и перезапустите бэкенд — он читает каталог при старте.

Таблицы создаются при первом запуске. Если позже меняется структура таблиц (новые поля), подключите миграции Alembic —
`create_all` новые столбцы в существующие таблицы не добавляет.

## ЮKassa

1. Договор с ЮKassa (юрлицо ООО «Чехлы Автостиль»), в личном кабинете — магазин 1avtochehol.ru.
2. Для проверки — тестовый магазин: ключ вида `test_…`, тестовые карты из документации ЮKassa.
3. Интеграция → Ключи API → `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` в `.env`; `PAYMENT_PROVIDER=yookassa`.
4. Интеграция → HTTP-уведомления: `https://1avtochehol.ru/api/payments/yookassa/webhook`, события `payment.succeeded`,
   `payment.canceled`, `refund.succeeded`.
5. Чеки 54-ФЗ: если подключены «Чеки от ЮKassa» или онлайн-касса — `YOOKASSA_RECEIPTS=1`. Ставку НДС (`YOOKASSA_VAT_CODE`)
   и признак расчёта для предоплаты (`YOOKASSA_PREPAY_MODE`: `partial_prepayment` или `advance`) подтверждает бухгалтер.
   При предоплате после отгрузки нужен второй чек (зачёт предоплаты) — это делает касса или API чеков ЮKassa; в коде пока не реализовано.
6. Другой провайдер (Т-Банк, Сбер, Robokassa) — новый класс в `app/payments/` с методами `create` и `fetch`, как `yookassa.py`.

## Уведомления

- Telegram: бот через @BotFather, добавить в группу менеджеров, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_IDS` (id группы, с минусом).
- Почта: `SMTP_*` (например, Яндекс 360: `smtp.yandex.ru`, порт 465, `SMTP_TLS=ssl`, пароль приложения), `MANAGER_EMAILS`.
- Ошибка отправки не теряет заказ: он уже в базе, а ошибка записана в историю заказа.

## Админка

- Первый пользователь — `python -m app.cli create-admin <логин>`, дальше — раздел «Пользователи» (роли: администратор, менеджер).
- Пароль — от 10 символов; после 5 неверных попыток вход блокируется на 15 минут; лимит попыток по IP.
- Двухфакторный вход: «Мой аккаунт» → «Настроить» (Яндекс Ключ, Google Authenticator). Включите всем.
- Желательно закрыть `/admin` по IP офиса (`ADMIN_IP_ALLOWLIST` или `allow/deny` в nginx).
- Сбросить пароль и 2FA: `python -m app.cli reset-password <логин>`.

## VIN

Клиент вводит VIN (достаточно первых 11 символов — серийный номер не нужен) или номер кузова праворульного «японца»
(`NZE141-6012345`). Сервер определяет:
1. производителя по первым трём символам (WMI) — мировой справочник `sources/wmi-world.json`;
2. модель и кузов по символам 4–8 (VDS) — правила по маркам `sources/<группа>.json`, у каждого правила источник и достоверность
   (`official` — документ производителя, `confirmed` — два источника или реальный VIN, `probable` — один источник, «вероятно»);
3. модельный год по 10-му символу — только у производителей, которые его так кодируют;
4. лекала каталога, подходящие по модели, кузову и году. Вариант салона (5/7 мест, сплошная спинка, подлокотник) по VIN не
   определить — клиент выбирает, менеджер сверяет.

Состав справочника (22.10.2026): 2 543 кода производителя по всему миру и таблица стран ISO 3780; 899 правил VIN и 621 код
кузова по 41 марке каталога. Лекала распознаются у 480 из 485 позиций каталога. Не распознаются: Chery Tiggo (2 лекала —
у Chery модель в VIN не кодируется), Isuzu Elf, Suzuki Solio и классическая ВАЗ-2121 (в каталоге нет поколения или
нет подтверждённого кода) — для них сайт определяет марку, а лекало выбирает клиент.
Источники правил: выписки ОТТС (Lada, УАЗ, ГАЗ, GM), отзывные списки производителей (UOKiK, Польша), NHTSA vPIC,
каталог drom.ru и Википедия (коды кузовов), реальные VIN из объявлений и торгов — у каждого правила ссылки в `sources`.
Поправки поверх исследований — `sources/overrides.json` (например, год у Ford Европы и России — 11-й символ, у Renault
российской сборки год не кодируется). Тест `tests/test_vin_sources.py` прогоняет 1 300 реальных VIN из исследований:
каждый должен попасть в лекала своего правила.

**База учится на заказах.** В карточке заказа менеджер подтверждает лекало («Подтвердить и запомнить») — сервер запоминает
начало VIN (8 символов) или код кузова, и следующему клиенту с такой машиной сразу предложит это лекало. Такие правила важнее
справочника; список и удаление — «VIN-справочник» в админке.

Проверка из консоли: `python -m app.cli vin XTA219010K0123456`, покрытие каталога: `python -m app.cli vin-coverage`.

## Безопасность — что сделано

- Цены, суммы, доставка и статусы оплаты — только на сервере; статус оплаты подтверждается запросом в ЮKassa.
- Проверка и очистка всех полей (длины, форматы телефона, e-mail, ИНН, VIN, перечни значений), ошибки по-русски с указанием поля.
- POST только с нашего домена (проверка Origin) — защита от подделки запросов с чужих сайтов.
- Антиспам: скрытое поле-ловушка, минимальное время заполнения формы, лимиты по IP; при необходимости — Яндекс SmartCaptcha
  (`SMARTCAPTCHA_*`). Подозрительные заявки помечаются «Спам», без оплаты и уведомлений.
- Лимиты: nginx (`limit_req`, `limit_conn`, таймауты, размер тела 64 КБ) + второй рубеж в приложении.
- Админка: scrypt-хеши паролей, серверные сессии (cookie `HttpOnly`, `Secure`, `SameSite=Strict`), CSRF-токен в каждой форме,
  блокировка перебора, 2FA, строгая CSP, роли; удаление записей — только администратор и только неоплаченных.
- Номер заказа для клиента — случайный идентификатор в ссылке (`thanks.html?order=…`), по номеру `AS-…` чужой заказ не открыть;
  в публичном статусе нет персональных данных.
- Согласие на обработку ПДн фиксируется (время, IP, документ). Служебные файлы (`backend/`, `.git`, `.env`, база) закрыты в nginx.
- В продакшене сервер не стартует с тестовой кассой, без `SECRET_KEY` и без https.

## Что нужно сделать вне кода

- **DDoS**: объёмную атаку не остановить ни приложением, ни nginx — нужен фильтр трафика перед сервером (DDoS-Guard, Qrator,
  Servicepipe, Yandex Cloud Smart Web Security, Cloudflare). Подключается сменой DNS.
- Политика обработки ПДн и уведомление Роскомнадзора об обработке ПДн (если ещё не подано).
- Обновления ОС и пакетов (unattended-upgrades), SSH только по ключам, firewall (открыты 22, 80, 443).
